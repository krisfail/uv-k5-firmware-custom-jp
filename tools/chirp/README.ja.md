# wrx-jp CHIRPドライバ

`wrx_jp.py`は，K1／K5 V3と旧UV-K5を1ファイルで扱います．K1／K5 V3はPY32F071プロファイル，旧UV-K5はDP32G030プロファイルです．

このリポジトリの対象機種では，CHIRPで`UV-K5 (wrx-jp RX-only)`を選択します．K1／K5 V3には`UV-K1 / UV-K5 V3 (wrx-jp RX-only)`を選びます．機種選択を誤るとメモリーマップが一致しないため，アップロード前に対象機種から全イメージをダウンロードして保存してください．

このドライバは受信専用です．送信周波数，送信トーン，PTT，出力設定を扱いません．FMプリセットは日本向けに`76.0–95.0 MHz`として読み書きします．FM登録数はK1/K5 V3が48件，旧K5が20件です．K1/K5 V3の追加RX機能状態と校正値は，アップロード対象から除外しています．

## 校正領域の保護

CHIRPのアップロードは，通常のチャンネル・VFO・設定だけを対象にした許可リスト方式です．旧UV-K5では`0x0000–0x1CFF`だけをアップロードし，校正領域を含む`0x1D00`以降を除外します．校正値の中心的な領域は`0x1E00–0x1EBF`です．全イメージのダウンロードには個体固有のデータが含まれ得るため，アップロード前のバックアップとして保存してください．

ファームウェアのエアコピー経路にも校正領域を避ける範囲チェックがありますが，UARTや保守用ツールなど別の低レベル書き込み経路まで同じ拒否条件があるとは限りません．これはCHIRPのアップロード経路に対する保護であり，校正領域の絶対的な書き込み禁止ではありません．校正データを変更する操作は行わず，復元が必要な場合だけ個体のバックアップから明示的に復元してください．書き込み範囲を変更するコードでは，境界を含むテストと復旧手順を先に更新します．

実機でのCHIRP読み書きは未検証です．まず読み取りだけを確認し，バックアップを保持してください．帰属・ライセンスは`NOTICE.md`と`LICENSE.txt`を参照してください．
