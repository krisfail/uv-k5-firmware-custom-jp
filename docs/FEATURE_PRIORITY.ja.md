# K5版 受信機能の優先度

この表は，DP32G030搭載の旧UV-K5向けwrx-jpで，フラッシュ容量と実機検証の負担を考慮して機能を選ぶための記録です．K5はK1／K5 V3より容量の余裕が小さいため，受信機としての有用性，サイズ，既存コードとの境界を分けて判断します．

この文書は人間の開発者向けの計画・容量判断資料です．利用者向けの機能説明は[README.ja.md](../README.ja.md)，AIエージェント向けの規則は[AGENTS.md](../AGENTS.md)を参照してください．

> 現行の採用・保留・除外の判定は[FEATURE_AUDIT.ja.md](FEATURE_AUDIT.ja.md)へ統合しました．この文書は，K5の容量制約と判断経過を残す補足資料です．実機試験は[HARDWARE_TEST_PLAN.ja.md](HARDWARE_TEST_PLAN.ja.md)を使用します．

## 現在の優先度

| 優先度 | 機能 | 状態 | 理由 |
| --- | --- | --- | --- |
| A | 国内FM放送，AM/FM受信，W/N/N-，周波数ステップ | 実装済み | 国内での基本受信に直結し，保存形式とドライバ境界を限定できる |
| A | 受信バンドプリセット，範囲スキャン，スキャン一時スキップ | 実装済み | 周波数入力の負担を減らし，受信専用用途で効果が大きい |
| A | RXExt，AUTOスケルチ，FM AGCガード，逆CTCSS | 実装済み | 受信品質と追加機能の一括管理に有用 |
| A | RSSI／音声レベル表示，スキャン候補確認 | 実装済み | 受信状態の判断に使える．送信機能や校正領域に依存しない |
| B | スキャン時のRSSI履歴・進捗表示の拡張 | 保留 | 有用だが表示更新，走査時間，コードサイズの増加を伴う |
| B | 永続化されたスキャン除外リスト | 保留 | 利便性はあるが，EEPROM形式・CHIRP境界・寿命への影響を検証する必要がある |
| B | FM局間隔・端点の厳密化 | 保留 | 日本向けには有用だが，既存CHIRPと76.0／95.0 MHz互換性を整理してから行う |
| C | メニュー説明，RX-only状態表示，日本語ラベル，コメント | 実装済み／継続 | サイズが小さく，操作ミスを減らせる |
| C | 送信系コードのビルド除外とRX-only境界テスト | 実装済み | 機能追加より先に，受信専用という前提を壊さないための基礎 |

## 容量上の判断

K5では，受信機能を一つ追加する前にmakeのtextとdecを確認します．送信専用のソースをビルド対象から外しても，すでに無効化されていたコードの再コンパイルだけでは大きな空きは生まれません．したがって，現時点では大型のスペクトラム解析や永続スキャン管理を無理に追加せず，既存の走査・表示・スケルチ処理の境界改善を優先します．

追加候補を採用する条件は次のとおりです．

1. 受信経路だけで完結し，RF送信・校正領域・外部保守領域へ依存しない．
2. RAMとフラッシュの増加量をビルド結果で確認できる．
3. スキャン停止，FM放送，AM，RXExt OFF，電源再投入を含むテストを追加できる．
4. 実機で確認できない部分は，利用者向け文書で保証として扱わない．

## ビルドから除外するもの

K5版のMakefileでは，AirCopy，REGA，TX1750，AM時送信，送信電力調整，F4HWNのRX/TXタイマーをRX専用版のビルド対象から外しています．UARTのデータ送信やSPI/I2Cの制御通信はRF送信ではないため，CHIRPや保守に必要な範囲で残します．
