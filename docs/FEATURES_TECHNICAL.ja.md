# wrx-jp 新機能技術詳細（旧UV-K5）

この文書は、DP32G030搭載の旧UV-K5向け日本語・受信専用版について、実装者・レビュー担当者が新機能、EEPROM境界、フォント、検証範囲を確認するための技術資料です。利用者が最初に読む文書ではありません。対象、書き込み前の注意、通常操作は[README.ja.md](../README.ja.md)、日常操作は[CHEATSHEET.ja.md](../CHEATSHEET.ja.md)を先に参照してください。

K1／K5 V3（PY32F071）の実装・メモリーマップは、別リポジトリ側のK1／K5 V3用技術資料を参照してください。このリポジトリのアドレスをK1へ流用してはいけません。

## 1. 正規の実装入口と前提

日本語・受信専用版は`Makefile`の`wrx-jp`ターゲットで作ります。主な定義は次のとおりです。

| 定義 | 役割 |
| --- | --- |
| `ENABLE_RX_ONLY=1` | 送信経路・送信系UIを無効化し、PTTをモニター操作にする |
| `ENABLE_JAPANESE=1` | 日本語メニューと拡張フォントを有効化する |
| `ENABLE_RX_AGC_GUARD=1` | 通常のFM受信時の急激なAGC変化を抑える |
| `ENABLE_FMRADIO=1` | FM放送機能を有効化する |
| `TARGET=wrx-jp` | 生成物を上流版と区別する |
| `EDITION_STRING=JP-RX-Only` | 無線機上の版の用途を明示する |

追加機能は、標準の設定・チャンネル記録をできるだけ保持しながら、旧UV-K5の内蔵EEPROMへ保存します。校正領域は利用者設定ではありません。

`RXExt`は追加した受信機能のマスター設定です。OFFで停止する対象はプリセット、SINGLE受信、メモリーバンク絞り込み、自動スケルチ、AGCガード、一時スキップです。受信専用制約、PTTモニター、日本語表示、FM放送の76.0–95.0 MHz制限は`RXExt`では解除されません。通常受信の4段階帯域幅は常時選択できます。

## 2. 受信専用ポリシー

- PTTは送信処理へ進まず、モニター操作として扱います。
- 送信系メニュー、VOX、DTMF calling、送信トーンなどは日本語・受信専用設定で無効化します。
- DUAL WATCHやCROSS BANDなど、送信経路を伴う状態から追加受信機能を起動しないよう、プリセット側にも拒否条件があります。
- この版は国内向け受信機として提供するもので、送信可能版の再有効化はこの機能仕様の対象外です。

## 3. 追加受信機能

K5の機能の意味はK1／K5 V3と共通ですが、プリセット数と保存方式が異なります。

### 3.1 受信モード

受信モードは`MAIN ONLY`、`DUAL RX`、`SINGLE`です。`SINGLE`は`RXExt`有効時だけ選択でき、VFO切替を抑制します。状態はグローバル設定へ保存されます。

### 3.2 通常受信の帯域幅

メニューの選択順は`W+` 25 kHz、`W` 20 kHz、`N` 12.5 kHz、`N-` 6.25 kHzです。`ACTION_Wn()`も`W+ → W → N → N- → W+`の順に切り替えます。

旧UV-K5のBK4819では、`W+`は`BK4819_REG_43=0x3628`、`W`は`0x3428`です。これはWIDE側の弱電界用RFフィルタ方針を2系統へ分けた既存レジスタ設定を、25／20 kHzの利用者向け表示へ対応付けたものです。`N`は12.5 kHz、`N-`は6.25 kHzです。

帯域幅と周波数ステップは独立設定です。ステップ選択には6.25／12.5／20／25 kHzが既に含まれ、FM放送など10 kHzのプリセットも個別に維持できます。帯域幅の拡張モードは、RX-only構成で標準チャンネル記録のbyte 7へ`0x80 | mode`として保存します。byte 4の標準WIDE/NARROW bit、byte 5のバンク属性、校正領域は変更しません。旧保存データにmarkerがない場合は、従来のbyte 4とWIDE+互換bitから安全に移行します。

### 3.3 自動スケルチ

自動スケルチは受信開始時などにRSSI、noise、glitchを8回、2 ms間隔でサンプリングします。平均値から次の6閾値を作り、通常の`BK4819_SetupSquelch()`へ渡します。

```text
open RSSI   = RSSI + 8       close RSSI   = RSSI + 4
open noise  = max(noise - 8, 0)
close noise = max(noise - 4, 0)
close glitch = glitch + 4     open glitch  = glitch + 8
```

各値は8 bit範囲へクランプします。自動スケルチの要求は一度消費すると再利用されず、`RXExt`または自動スケルチがOFFなら適用しません。

### 3.4 AGCガード

`ENABLE_RX_AGC_GUARD`時、`RXExt`有効、通常のFM受信、スキャン停止中、FM放送モード外だけで動作します。周波数ごとに前回サンプルを保持し、RSSI差が12以上または受信ゲイン差が8以上になった場合にAGCを一時停止します。停止保持はスケジューラ30回で、満了時にAGCを再有効化します。AM_FIXなど別の無線再構成が管理するAGC状態を上書きしないよう、通常FMに限定しています。

### 3.5 メモリーバンク

チャンネルにはバンク番号0～8を持たせます。選択バンクが0（ALL）のときは全チャンネル、1～8のときは一致するチャンネルだけをメモリースキャン候補にします。

### 3.6 一時スキップ

スキャン中の一時スキップは周波数をRAM上の最大16件のリストへ追加します。同一周波数は重複登録せず、満杯の場合は追加しません。周波数スキャンとメモリースキャンの両方で候補を確認し、候補をすべて飛ばした場合も無限ループにならないよう試行回数に上限を設けています。電源再投入やスキャン範囲のリセットで消えます。

### 3.7 受信バンドプリセット

周波数表示中に`STAR`で一覧を開き、`UP/DOWN`で選択、`M`で適用、`STAR`で適用後にスキャン開始、`EXIT`でキャンセルします。周波数モード、スキャン停止、デュアル受信・クロスバンド無効などの条件を満たさない場合は適用しません。適用時は候補周波数を一つずつ`RX_freq_check()`で検証します。

旧UV-K5では容量制約のため、プリセットは次の8件です。

| 名前 | 範囲 (MHz) | 刻み | 変調 / 帯域 |
| --- | ---: | ---: | --- |
| AIR VHF | 118.000–137.000 | 25 kHz | AM / NARROW |
| AIR UHF | 225.000–400.000 | 100 kHz | AM / NARROW |
| TOKUSHO | 422.050–422.300 | 12.5 kHz | FM / NARROW |
| FIRE | 466.350–466.550 | 12.5 kHz | FM / NARROW |
| 140 HAM | 144.000–146.000 | 20 kHz | FM / WIDE |
| 430 HAM | 430.000–440.000 | 20 kHz | FM / WIDE |
| MAR SHIP | 156.025–157.425 | 25 kHz | FM / WIDE |
| MAR SHORE | 160.625–162.025 | 25 kHz | FM / WIDE |

プリセットは実行時のスキャン範囲であり、VFO切替・電源再投入でリセットされます。

### 3.8 FM放送と日本向け仕様の照合

日本のFM放送局周波数の目安は76.1–94.9 MHzです。総務省系NICTの資料でも、臨時災害放送局用FM機器の送信可能周波数を76.1–94.9 MHz、電波型式をF3E/F8E（モノラル／ステレオ）として示しています（[NICT公式資料](https://www2.nict.go.jp/resil/book/2024/46132-book/pageindices/index87.html)）。

現行実装は次の構成です。

| 項目 | 現行実装 | 判定 |
| --- | --- | --- |
| RFハードウェア | BK1080の76–108 MHzモード | 日本向け範囲を包含するため妥当 |
| UI・設定・CHIRP範囲 | 76.0–95.0 MHz、0.1 MHz単位 | 局範囲の外側に100 kHzずつ余裕がある |
| 周波数刻み | 内部単位で1、すなわち100 kHz。`FM_Space`の選択肢は無効化 | 日本の100 kHz級の局間隔に適合 |
| ステレオ／FM復調 | BK1080のFM放送モードへ委譲 | ソース上でモノラル／ステレオを個別選択する機能はない |

結論として、76.1–94.9 MHzの日本の局を受信する用途には概ね対応しています。ただし、現在は76.0 MHzと95.0 MHzも入力・スキャン端点として許可するため、仕様範囲と厳密に一致していません。これは受信機のガード範囲としては有害ではありませんが、厳密に合わせるならUI・自動選局・CHIRPの検証範囲を761–949（0.1 MHz単位）へ変更し、BK1080の内部ハードウェア範囲だけを760–950のまま保持する設計が候補です。この作業では互換性を優先してコード変更は行っていません。

### 3.9 スキャン候補の受信確認

周波数スキャンがVHF帯の第2高調波に相当する候補を検出した場合、候補周波数だけで判定を確定しません。候補の半分の周波数へ一度同調してRSSIを読み、その後候補周波数へ戻して再度RSSIを読みます。基礎周波数側が十分強い場合は、CSSスキャンへ渡す周波数を基礎周波数へ置き換えます。これにより、VHF帯で高調波を実信号として扱う誤停止を抑えます。

この確認は走査中の一時的な受信状態だけを使い、メモリー、校正データ、チャンネル設定を変更しません。K5では容量を抑えるため、適応的な全帯域スキャンや追加の履歴保持は含めず、この候補確認だけを有効にしています。

AM／USBではBK4819のCSS検出器を使用できないため、F+STARによるCSSスキャン起動を拒否し、短いエラー音だけを返します。FM受信やFM放送スキャンの操作には影響しません。

### 3.10 FM受信時のゲイン制御

RXExt有効、通常のアナログFM受信、非スキャン時だけ、RSSIと受信ゲインの変化を10 ms周期で監視します。RSSIが-58 dBm以上になった場合は、ドライバの固定ゲイン設定を最小側へ切り替え、-78 dBm以下まで戻った時点で自動ゲイン制御へ復帰します。急なレベル変化には中間の固定ゲインを200 msだけ適用し、音声のポンピングを抑えます。

FM放送モード、AM／USB、スキャン中、RXExt無効時はこの処理を行いません。これらの状態のAGCは、既存の無線機再設定処理に任せます。設定値やcalibration領域への書き込みはありません。

### 3.11 スケルチ自動校正の外れ値抑制

自動スケルチ校正は8回のRSSI・ノイズ・グリッチ測定から各項目の最大値と最小値を1回ずつ除外し、残る6回の平均で既存の開閉ヒステリシスを計算します。短いクリックや一時的なノイズバーストが、以後のスケルチ基準へそのまま残ることを抑える設計です。値は現在のVFO設定へ反映するだけで、校正テーブルは変更しません。

### 3.12 スキャンワッチ同時

RXExt有効かつ`TDR=DWR`のとき、メモリーチャンネル走査の次候補へ、受信側とは反対のVFOに表示されている有効なメモリーチャンネルを挿入します。これにより、走査対象とワッチ対象を同じ走査サイクルで確認できます。周波数モードのVFOは対象にせず、走査停止時の範囲復元を曖昧にしないようにしています。新しいEEPROM項目は追加していません。

### 3.13 メニュー簡易ヘルプ

受信専用版で意味を確認しにくい項目の下端へ、短い英数字の説明を表示します。SQLは`AUTO=measure noise`、帯域幅は`W+25 W20 N12 N-6`、RXExt／バンク項目は機能の役割を示します。表示は補助文だけであり、選択値や保存形式は変更しません。

旧UV-K5では、音声サンプルを取得して周波数分解するスペクトラム表示は採用していません。`app/spectrum.o`単体で約6.6 KiBを要し、既存の受信専用イメージの空き容量では安全に収まらないためです。

## 4. EEPROM配置と校正領域

### 4.1 追加グローバル領域

`RX_FEATURE_EEPROM_BASE`は`0x1F90`です。これは標準設定ブロックの後ろに置く8-byteページで、校正領域を上書きしません。

| byte | 内容 |
| ---: | --- |
| 0–1 | magic `RX` (`0x52, 0x58`) |
| 2 | format version。1を読み取り可能、保存は2 |
| 3 | flags: bit0=SINGLE、bit1=AUTO SQL、bit2=RXExt enabled |
| 4 | 選択バンク。0=ALL、1–8=バンク |
| 5 | 予約、現在は0 |
| 6–7 | byte 0–5へCRC16-CCITT、little-endian格納 |

未初期化・CRC不一致・範囲外のバンクは安全な既定値へ戻します。既定値はRXExt有効、全バンク、WIDE+有効です。version 1は読み取り時にRXExt有効として扱い、保存時にversion 2へ更新します。

### 4.2 チャンネルメタデータ

チャンネル`n`の追加メタデータは、既存のチャンネル記録内の次の位置にあります。

```text
record offset = n * 16
metadata read/write page = record offset + 8, length 8
byte 4 bit 7 = 旧WIDE+互換bit（その他のbitは保持）
byte 5 high nibble = bank 0–8（low nibbleは保持）
byte 7 bit 7 = extended bandwidth marker、bit 1–0 = W+／W／N／N- mode
```

標準フィールドを丸ごと置き換えず、読み出した8 bytesへ必要なbitだけ反映して保存します。新しい保存処理を加える場合も、この予約bitと標準EEPROMの境界を変更してはいけません。

### 4.3 calibration保護

旧UV-K5の校正テーブル`0x1E00–0x1EBF`は受信拡張の保存先ではありません。`tools/chirp/wrx_jp.py`は通常のアップロード・ホワイトリストから校正範囲を除外します。ただし、UARTの低レベルコマンドや外部保守ツールまで同じ拒否条件を保証するものではありません。書き込み前に個体の全イメージとcalibrationを保存してください。詳しい境界は[CHIRP技術ガイド](../tools/chirp/README.ja.md)を正とします。

## 5. 日本語表示とフォント

### 5.1 現行エンコーディング

メニュー文字列はUTF-8ではなく、ファームウェア内の1 byteコードです。`font.c`の日本語領域は`0x80–0xDF`で、大文字テーブル`gFontBig`と小文字の`gFontSmallJapanese`を使います。大文字は1 glyph 14 bytes（7列×2ページ）、小文字は6 bytesの形式です。

旧UV-K5では長音「ー」を別の拡張glyphへ追加せず、メニュー文字列でASCIIハイフン`-`へ符号化します。そのため既存の大文字・小文字ハイフンを共有でき、K1で問題になった大文字長音用の追加glyph変換は必要ありません。この仕様を変更する場合は、全メニュー文字列と表示幅のテストを同時に更新してください。

`font.c`には`rainy-knight/uv-k5-jp`由来の字形を使用していることとApache-2.0の帰属がコメントで明記されています。再配布時もこの帰属を削除しないでください。

### 5.2 フォント候補の評価

| 候補 | ライセンス / 形式 | 採否 |
| --- | --- | --- |
| 現行Rainy由来データ | `font.c`の帰属ではApache-2.0。現行の7×14／小文字形式へ適合済み | 採用継続 |
| [M+ Fonts](https://mplusfonts.github.io/) | SIL Open Font License。小型表示向け系列もあるが、現行bitmap配列への変換が必要 | 今回は不採用 |
| [PixelMplus](https://github.com/itouhiro/PixelMplus) | M+系ライセンス、アウトラインTrueType。10/12 pixel向けで、埋込み配列への変換・表示確認が必要 | 今回は不採用 |
| [Misaki](https://littlelimit.net/misaki.htm) | 8×8 bitmap、M+ Fonts license。現行7×14大文字と6 byte小文字へ変換する工程が必要 | 今回は不採用 |
| [GNU Unifont](https://unifoundry.com/unifont/index.html) | GPL+例外 / SIL OFLのデュアルライセンス、8/16×16グリッド。容量と字形サイズが現行構造に不適合 | 不採用 |

既存フォントは対象コード範囲、容量、表示基線、Apache-2.0帰属をすでに満たしています。別フォントへ交換すると、変換スクリプト、字形レビュー、ライセンス文書、容量評価を新たに必要とするため、今回の目的には現行フォントの継続が最小リスクです。

## 6. 検証と既知の未検証範囲

ホスト側の正規確認は次のコマンドです。

```powershell
python -m unittest discover -s tests -p "test_*.py" -v
make -j2
```

主な回帰テストは`test_receive_only_policy.py`、`test_rx_feature_state.py`、`test_receive_band_presets.py`、`test_receive_scan_skip.py`、`test_chirp_wrx_jp.py`です。これらはソース定義、設定形式、境界条件、CHIRPの読み書き対象を検査しますが、RF性能やLCDの見え方を検査するものではありません。

実機では、対象個体のバックアップ後に表示版、PTTモニター、FM 76.1–94.9 MHzの局、76.0／95.0 MHz端点の扱い、WIDE+、RXExt、プリセット、バンク、スキャンスキップ、電源再投入後の設定復元を確認してください。特に日本語と欧文の基線、K1／K5 V3でWIDE+がWIDEと同じRF設定になること、CHIRPの読み取り後の校正データ不変性は、静的テストだけでは保証されません。

## 用語

- **RXExt**: 追加受信機能をまとめて切り替える永続設定。
- **W+ / W / N / N-**: 通常受信の25／20／12.5／6.25 kHz設定。旧UV-K5ではW+とWが異なるREG43設定になる。
- **bank**: メモリースキャンの論理グループ。0は全バンク。
- **calibration**: 個体ごとの校正データ。通常の利用者設定・CHIRPメモリーとは別に保護する。
- **予約bit**: 標準形式では使わないbit。利用時は他のbitを保持する必要がある。

実装の変更時は、対応するソース、ホストテスト、この資料、利用者向けREADMEの役割を分けて更新してください。未検証の結果を実機保証として記載しないでください。
