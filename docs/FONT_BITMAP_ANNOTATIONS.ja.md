# フォント／ビットマップの割り当て台帳

この文書は、表示文字を追加する前に既存のフォントとビットマップの割り当てを確認するための台帳です。ここでいうコードは、ファームウェア内部の1バイト文字コードであり、Unicodeそのものではありません。

人間の開発者向けの台帳であり、利用者向けの表示案内ではありません。利用者向けの説明は[README.ja.md](../README.ja.md)、AIエージェント向けの規則は[AGENTS.md](../AGENTS.md)を参照してください。

## 既存の文字コード

| 範囲 | 用途 | 備考 |
| --- | --- | --- |
| `0x21`–`0x7E` | ASCII大文字・小文字・記号 | `gFontBig`の標準領域 |
| `0x7F` | 空き／互換領域 | 現在は空グリフ |
| `0x80`–`0x97` | 既存の日本語大グリフ | K5/K1で共通の意味を維持する |
| `0x98` | 日本語大グリフ「専」 | 公開フォント（Izumi 16）の線構造を手掛かりに独立再構成 |
| `0x99` | 日本語大グリフ「用」 | 公開フォント（Izumi 16）の線構造を手掛かりに独立再構成 |
| `0x9A`–`0xA0` | 予約領域 | K5/K1の大・小フォントで共通して空いている候補 |
| `0xA1`–`0xDF` | 既存拡張領域 | 個別のatlasで占有状態を確認する。未使用と推測して再利用しない |
| `0xE0`–`0xFF` | K1側の拡張領域 | K5の`FONT_CODE_MAX`とは異なるため、共通文字には使用しない |

特大字形は`gFontJapaneseExtraLarge`に分離しています。10列×2ページ（20 bytes）で、K5の容量制約から現在は`0x98`（専）、`0x99`（用）の2スロットだけを使用しています。起動画面の`受信専用`は4字すべてを低解像度向けに再構成した通常大字形で描画します。通常大字形と同じコードを使う文字もありますが、同じ文字を常に特大で描画する意味ではありません。表示場所に応じて通常描画と特大描画を使い分けます。

`0x80`–`0x97`の意味は次のとおりです。

`受 信 変 調 追 加 保 存 削 除 名 長 短 押 音 電 源 更 圧 表 示 画 面 無`

K5では長音「ー」を大フォントへ新設せず、既存のASCIIハイフン（`0x2D`）を日本語メニューでも共有します。K1には大・小フォントの`0xE0`として長音が存在します。機種間で同じ文字を追加するときは、この差を吸収する表示文字列側の分岐を先に検討します。

## 大字形の縦位置契約

大字形は欧文・日本語とも16行（7列×2 OLEDページ）を使い、表示行0–1を上余白、表示行2–11を字形領域、表示行12–15を下余白とします。フォント配列はこの表示座標へ正規化済みで、描画側に日本語だけの補正を追加しません。編集画面も同じ行番号を表示し、上2行・下4行を色分けします。

字形の上下余白を変更する場合は、片方の文字種だけを移動せず、この契約を欧文・日本語の両方へ適用してください。点灯範囲が字形領域から外れる場合は、atlasと実機で確認します。

## atlasによる確認

```powershell
python -X utf8 tools/render_bitmap_atlas.py `
  --source font.c `
  --source bitmaps.c `
  --out tmp/uv-k5-bitmap-atlas-annotated
```

`bitmap_atlas_inventory.json`には、フォント配列について次の情報が含まれます。

- コードポイント、ソース上の注釈、占有／空き状態
- グリフの元バイト列（重複比較用）
- 指定初期化子で省略された空スロット

`bitmap_atlas.svg`は形状の目視確認用です。ビットマップ配列は`BITMAP_*`のシンボル名と元配列のバイト列を記録し、文字コードとは別の資産として扱います。

## 追加時の規則

1. まず両機種のatlas inventoryでコードの占有状態とバイト列を確認する。
2. 既存グリフと同じ意味のコードを新設しない。共通化する場合はK5/K1双方に同じコード注釈を付ける。
3. 共通の新規文字は、現時点では`0x9A`–`0xA0`から必要数だけ割り当てる。追加前に再度inventoryを生成する。
4. C配列の行または指定初期化子に、コードと意味を示す短いコメントを付ける。
5. atlas、ソースコメント、表示文字列の対応を確認してから実機用の文字を追加する。

inventory確認後、起動画面の「受信専用」に必要な大グリフとして`0x98=専`、`0x99=用`を公開フォントから変換して実装しました。K5では`font.c`の連続配列、K1では`App/japanese_font.c`の指定初期化子に同じ14-byte字形を保持しています。小フォントには追加せず、現時点では大フォント専用です。次に追加する文字は、空き領域`0x9A`–`0xA0`と再生成したinventoryを確認してから割り当てます。

今回の`font-glyph-0x98.json`／`font-glyph-0x99.json`は、通常大字形の正本であるC配列へ反映済みです。JSONは編集結果の受け渡し用で、正本ではありません。特大字形は公開フォントの線構造を手掛かりに独立再構成した10×16セルです。出所と変換規則は[FONT_SOURCES.ja.md](FONT_SOURCES.ja.md)に記録しています。形状を変更するときは`font_editor.html`で10×16のグリッドを選択し、正本のC配列とatlasを更新してください。
