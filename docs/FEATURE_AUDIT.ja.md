# K5版 機能監査と採否

この文書を、DP32G030搭載の旧UV-K5向け`wrx-jp`における機能採否の現行台帳とします。利用者向けの操作説明は[README.ja.md](../README.ja.md)、開発手順は[DEVELOPMENT.md](../DEVELOPMENT.md)、AIエージェント向けの規則は[AGENTS.md](../AGENTS.md)に分けています。

## 判断基準

受信機としての価値、安全性、フラッシュ／RAM、既存の保存形式への影響、実機での確認しやすさの順に判断します。送信、送信出力の校正、送信を前提とする保守機能は、この版の目的外です。ソースに残る上流互換コードは、通常プロファイルのMakefileで強制的にビルド対象外とします。

## 残す機能

| 分類 | 機能 | 採用理由・境界 |
| --- | --- | --- |
| 安全 | RX-only、PTTモニター、TX要求時の`TX DISABLE` | RF送信経路を持たせず、PTTを受信モニターへ割り当てる |
| 受信 | AM/FM、W+ 25 kHz、W 20 kHz、N 12.5 kHz、N- 6.25 kHz | 受信幅を明示的な4段階として扱う |
| 受信 | 日本向けFM放送、周波数ステップ、RXExt | 国内受信での入力負担を減らす |
| 走査 | バンドプリセット、範囲スキャン、スキャン一時スキップ | 受信専用機としての中心機能 |
| 状態 | RSSI／音声レベル、FM AGCガード、AM補正、感度を調整したスケルチ | 弱い信号の確認と受信安定性に使う |
| 設定 | 逆CTCSS、プリセット、バンク、チャンネル名、電源再投入後の状態復元 | 受信設定として完結し、既存保存境界を越えない |
| UI | 日本語メニュー、起動画面、簡易ヘルプ、フォントatlas、フラッシュライト | 操作の誤解を減らし、容量内で維持できる |
| 接続 | CHIRP、UART（低レベル校正操作を除く） | 通常のメモリー管理に必要。calibration領域は通常経路から除外 |

## 容量と検証次第で採用する機能

| 機能 | 採用条件 |
| --- | --- |
| スキャン進捗・RSSI履歴の拡張 | 走査時間、RAM、表示更新の増加を測定し、停止操作を実機で確認できること |
| 永続スキャン除外リスト | EEPROM寿命、CHIRP範囲、旧設定との互換性を定義できること |
| 大型スペクトラム表示 | K5のフラッシュと走査時間を測定し、受信専用の基本機能を圧迫しないこと |
| 追加の日本語字形 | ライセンスを確認し、atlas・ソース・実機LCDの三者を一致させること |

現時点では上記を無理に有効化しません。特にフルスペクトラムはK5の制約に対して優先度が低く、現在の通常ビルドでは無効です。

## RX専用版から外した機能

次の機能は、単にメニューから隠すだけでなく、通常ビルドの強制フラグで無効化しています。ソースを残すものは、上流互換性と差分追跡のためです。

- RF送信、送信電力・送信帯域の変更、AM時送信、1750 Hz送信、VOX、TOT、アラーム、DTMF calling
- AirCopy、REGA、送信領域のF Lock、F_CAL、電池校正メニュー
- UARTからのBKレジスタ書き換え、RAW demodulator、AGC内部値表示、band scope
- ゲーム、スクリーンショット、スペクトラム、充電電流調整、rescue操作、音量拡張
- リセットチャンネル、PMR、GMRS／FRS／MURS、デバッグ、RX/TXタイマー

UARTそのものとCHIRP通常操作はRF送信ではないため残します。ただし、低レベル保守コマンドをRX-onlyの安全境界と同一視しません。

## 変更時の確認

1. `Makefile`の強制無効化境界、メニューの条件コンパイル、PTTの分岐を確認する。
2. `make test`を実行する。
3. `make -B`で`text`、`data`、`bss`、`dec`を記録する。
4. [HARDWARE_TEST_PLAN.ja.md](HARDWARE_TEST_PLAN.ja.md)を実機で埋める。
5. フォントを変更した場合は、[BITMAP_ATLAS.ja.md](BITMAP_ATLAS.ja.md)と実機表示を確認する。
